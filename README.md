## Лабораторная работа №12

### 1. Порядок байт

В структуре `sockaddr_in` мы принудительно переворачивали байты порта и IP-адреса, потому что эти поля должны храниться в **сетевом порядке байт** (Big-Endian). Это требование сетевых протоколов TCP/IP.

Процессоры архитектуры x86-64 используют порядок байт **Little-Endian**. Это означает, что младший байт числа записывается в память первым. Например, порт `8080` в шестнадцатеричном виде равен `0x1F90`. При хранении в памяти на x86-64 он был бы записан как `90 1F`, то есть младший байт `0x90` идёт первым.

Однако сетевые протоколы передают многобайтовые числа в порядке **Big-Endian**: сначала передаётся старший байт, затем младшие. Поэтому порт `8080` должен быть записан в структуре как `90 1F`, что в NASM удобно задать как `dw 0x901F`.

Аналогично IP-адрес `127.0.0.1` в шестнадцатеричном виде равен `0x7F000001`. В сетевом порядке байт он записывается как `01 00 00 7F`, поэтому в коде используется значение `dd 0x0100007F`.

Таким образом, фундаментальная разница заключается в следующем:

- **Little-Endian** — порядок байт, используемый процессором x86-64: младший байт хранится первым.
- **Big-Endian** — сетевой порядок байт, используемый протоколами TCP/IP: старший байт хранится и передаётся первым.

Если не выполнить преобразование порядка байт, ядро или сетевой стек интерпретирует порт и IP-адрес неправильно. Например, вместо порта `8080` программа попыталась бы подключиться к другому порту.

### 2. Анализ регистров

Если сервер `netcat` не был запущен, системный вызов `connect` завершится ошибкой `ECONNREFUSED`, то есть «в подключении отказано».

При отладке программы в GDB результат системного вызова будет находиться в регистре **RAX**. Так как мы работаем с сырым ассемблерным кодом и используем инструкцию `syscall`, ядро возвращает ошибку непосредственно в этот регистр.

Код ошибки будет представлен как **отрицательное число**:

```text
RAX = -111
```

Число `111` соответствует константе `ECONNREFUSED`. В шестнадцатеричном виде в 64-битном регистре это значение будет выглядеть так:

```text
RAX = 0xFFFFFFFFFFFFFF91
```

Это то же самое число `-111`, но записанное в дополнительном коде.

Ядро Linux сигнализирует об ошибке следующим образом: при успешном выполнении системного вызова в `RAX` возвращается неотрицательное значение. Если произошла ошибка, ядро помещает в `RAX` отрицательное значение `-errno`. Например:

- успешный `connect` возвращает `0`;
- ошибка `ECONNREFUSED` возвращает `-111`;
- ошибка `EPIPE` возвращает `-32`.

В программах, использующих библиотеку glibc, обёртка системного вызова обычно преобразует отрицательное значение в `-1`, а положительный код ошибки записывает в переменную `errno`. Но в нашем NASM-коде мы работаем с системными вызовами напрямую, поэтому видим исходное значение `-111` именно в регистре `RAX`.

### 3. Сравнение абстракций

Метод высокого уровня `socket.send()` в Python в конечном итоге сводится к системному вызову ядра Linux и заполнению регистров процессора.

Цепочка преобразования выглядит следующим образом:

1. В Python создаётся объект сокета, например:

```python
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("127.0.0.1", 8080))
s.send(b"Hello")
```

2. Объект `socket` хранит файловый дескриптор сокета, который ранее был получен от ядра при вызове `socket()`.

3. При вызове метода `send()` интерпретатор Python обращается к реализации модуля `socket`, написанной на языке C.

4. Реализация на C вызывает функцию библиотеки libc, например `send()` или `sendto()`.

5. Функция libc подготавливает аргументы для системного вызова и помещает их в регистры процессора:

- номер системного вызова — в `RAX`;
- дескриптор сокета — в `RDI`;
- указатель на буфер с данными — в `RSI`;
- длину передаваемых данных — в `RDX`.

6. Затем выполняется инструкция `syscall`. Процессор переходит из пользовательского режима Ring 3 в режим ядра Ring 0.

7. Ядро Linux принимает данные, передаёт их сетевому стеку и отправляет через TCP-соединение.

8. После выполнения системного вызова ядро возвращает результат в регистр `RAX`:

- при успехе — количество реально отправленных байт;
- при ошибке — отрицательное значение `-errno`.

Таким образом, в нашем NASM-коде мы выполняем те же действия, что и Python, но напрямую:

| Действие | Python | NASM |
|---|---|---|
| Создание сокета | `socket.socket()` | `syscall` №41 |
| Подключение к серверу | `socket.connect()` | `syscall` №42 |
| Отправка данных | `socket.send()` | `syscall` №1 (`write`) |
| Получение результата | Число байт или исключение | Значение в регистре `RAX` |
| Обработка ошибки | Исключение Python | Отрицательное значение в `RAX` |

Следовательно, `socket.send()` в Python — это высокоуровневая абстракция, которая скрывает от программиста работу с файловым дескриптором, буфером памяти, регистрами процессора и системным вызовом ядра. В NASM все эти этапы выполняются вручную.
